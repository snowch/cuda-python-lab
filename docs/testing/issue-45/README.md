## How source and answers are owned

Each fixture has a permanent short ID scoped by the lesson. Each phase has a permanent lesson-scoped task ID, its original numbered instruction, a fixture ID, a source anchor or lesson fallback, its starting edits, learner action and evidence. Multi-case instructions are split at the point where the learner changes fixture or needs to distinguish an earlier edit from a fresh starter. The original ordering and tasks remain visible in the task selector. A selected case without a numbered task opens in free exploration.

Choosing a task selects its fixture and reads the learner’s effective program. The editor keeps the lesson’s shared kernel and the host draft for that case. Preparation compares the complete program byte for byte, including host instrumentation. When it differs, the guide names the source that would change. For example, unstable softmax starts with the row-sum print from the previous task, while the 37-column task starts with a clean, stabilized kernel and the wide fixture’s host. The learner explicitly chooses whether to prepare or keep experimenting.

Preparation stores the visible program, the exact case-specific program slot, the prior shared kernel and the installed kernel under `preparations[lesson][fixtureId]`. A null case slot or shared kernel records the absence of an explicit draft. Undo restores the two original ownership units in the same transaction, including the absence of an override. It also preserves intervening shared-kernel edits in recovery. Undo swaps the two programs, including host changes made after preparation. Replacing an occupied undo slot during a later preparation archives its previous value under the existing bounded recovery policy. A full archive or failed write retains pending edits for export and retry. The UI announces that the undo copy is available after the transaction commits. If a write fails, it directs the learner to export or retry. The ordinary **Restore starter** and **Undo restore** retain their own independent slot. A fresh database read checks the open text, case, selected task and undo version before a preparation proceeds.

The optional prediction is explicitly labeled for its selected case. All tasks using that case share its single named question and answer. A different case has a separate `caseAnswers[lesson][fixtureId]` path. Conflicts, backups, storage failures, stale previews and explicit loading use the existing transaction model. New runs carry the fixture ID and complete source. Older results use their existing case-specific slot. Free edits continue to execute from the open editor, including when the output intentionally differs from the starter or when the same array can arise from two different programs.

Migration is non-destructive. A one-case lesson can display its previous answer unambiguously. Once the learner writes a new answer, the original remains available separately. A multi-case lesson exposes its unassigned earlier answer under **Earlier lesson prediction**. The original stays in `predictions[lesson]`, including through reloads. No migration write or guessed assignment is needed. PR #44’s transactional writer preserved the new fields during the tested mixed-build sequence. The pre-transactional writer can still lose an unobserved edit between a mirror read and write. Keep an export or copy from older open tabs and finish the managed restart before resuming edits. ## Reproduction and limits

Use a clean checkout with Node 22 or later. Point Playwright at an installed Chromium or install the browser in the repository instructions. Keep each suite’s build directory independent while testing.

```sh
npm ci
export PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium
npm test
npm run test:runner
GUIDE_EVIDENCE=file:///tmp/cuda-guided-runs/ node docs/testing/issue-45/run-guides.mjs
node docs/testing/issue-45/result-provenance.mjs
CAPTURE_DIR=/tmp/cuda-guided-screens AXE_JS=/path/to/axe.min.js node docs/testing/issue-45/inspect.mjs
OLD_DIST=/path/to/built-main/dist node docs/testing/issue-45/check-upgrade.mjs
BASE_DIST=/path/to/built-main/dist node docs/testing/issue-45/baseline.mjs
```
